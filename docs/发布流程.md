# 自动打包与发布流程

推送形如 `v1.0.0+1` 的 tag 即触发 GitHub Actions 自动打包（版本号 + 构建号）。

## 一、一次性配置：仓库 Secrets

打开仓库 `Settings → Secrets and variables → Actions`，新增以下 4 个 Secret：

| Secret | 值 |
| :-- | :-- |
| `KEYSTORE_BASE64` | 签名文件的 base64（生成方式见下） |
| `KEYSTORE_PASSWORD` | 签名库口令（见本地 `android/key.properties` 的 `storePassword`） |
| `KEY_PASSWORD` | 密钥口令（见本地 `android/key.properties` 的 `keyPassword`） |
| `KEY_ALIAS` | 密钥别名，`printer` |

生成 `KEYSTORE_BASE64`（在项目根目录执行，直接复制到剪贴板）：

```bash
base64 -i android/app/printer-release.jks | pbcopy
```

> 签名文件本身不入库（`.gitignore` 已排除 `*.jks` 与 `key.properties`），
> CI 构建时从 Secret 还原，避免密钥泄露。

## 二、发版

1. 确认 `main` 已是最新。
2. 打 tag 并推送（tag 格式 `v版本号+构建号`）：

   ```bash
   git tag v1.0.0+1
   git push origin v1.0.0+1
   ```

3. 推送后工作流自动执行：
   `flutter analyze` → `flutter test` → 构建 arm64 release APK →
   上传 Actions 产物 → 创建 Release 并附带 APK。

## 三、产物

- **Actions 产物**：仓库 `Actions` 页对应运行记录里的 Artifacts（`label-printer-v1.0.0+1`）。
- **Release 附件**：仓库 `Releases` 页对应 tag 下的 `label-printer-v1.0.0+1.apk`，可直接下载安装。

## 四、版本号规则

| 部分 | 示例 | 说明 |
| :-- | :-- | :-- |
| 版本名 | `1.0.0` | 传给 `--build-name` |
| 构建号 | `1` | 传给 `--build-number`，对应安卓 `versionCode` |

每次发版请递增构建号（如 `v1.0.0+2`），否则安卓无法覆盖安装新包。

## 五、手动本地打包（备用）

```bash
flutter build apk --release --target-platform android-arm64
```

产物：`build/app/outputs/flutter-apk/app-release.apk`。
